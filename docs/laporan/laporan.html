BAB 1 Pendahuluan

1.1 Latar Belakang

Kafe dan kedai makanan kini semakin ramai dikunjungi, tetapi proses pemesanan di banyak kedai kecil masih dilakukan secara lisan atau dicatat di kertas. Cara ini membuat pelanggan harus menunggu di kasir, catatan khusus seperti less sugar atau sambal dipisah mudah terlupa, dan pemilik kedai sulit mengetahui sisa porsi serta menu yang paling laku.

Untuk menjawab masalah tersebut dibuat Delights, aplikasi mobile pemesanan makanan untuk kedai SweetnFresh. Pelanggan dapat menjelajah katalog menu, melihat level pedas, suhu sajian, dan estimasi waktu saji, menambahkan menu ke keranjang beserta catatan per item, lalu checkout untuk makan di tempat, dibawa pulang, atau diantar. Admin/kasir kedai dapat mengelola kategori dan menu, memproses status pesanan, serta memantau penjualan melalui dashboard dan grafik.

1.2 Tujuan

  • Membangun aplikasi Flutter dengan arsitektur GetX untuk state management, routing, dan dependency injection.
  • Merancang database relasional ternormalisasi (5 tabel) di MySQL XAMPP yang diakses melalui REST API PHP.
  • Menyediakan alur pemesanan lengkap: katalog → keranjang (dengan catatan) → checkout → struk PDF, dengan stok porsi yang selalu konsisten.
  • Menyediakan fitur admin/kasir: CRUD kategori & menu, ubah status pesanan, dan dashboard penjualan.

3.4 Normalisasi

  • UNF — satu nota pesanan memuat data pemesan dan daftar menu yang berulang (nama menu, kategori, harga, jumlah) di satu baris.
  • 1NF — grup berulang dipecah sehingga setiap item pesanan menjadi baris tersendiri dan semua kolom bernilai atomik; kunci komposit (nomor_pesanan, nama_menu).
  • 2NF — ketergantungan parsial dihilangkan: atribut yang hanya bergantung pada nomor pesanan dipindah ke pesanan, atribut yang hanya bergantung pada menu dipindah ke menu, sisanya (jumlah, catatan, subtotal) menjadi detail_pesanan.
  • 3NF — ketergantungan transitif (menu → kategori → nama kategori) dihilangkan dengan memisahkan tabel kategori; menu cukup menyimpan kategori_id dan nama kategori diambil lewat JOIN. Keranjang disimpan di tabel keranjang yang hanya berisi menu_id, jumlah, dan catatan.

Kolom nama_menu dan harga_satuan pada detail_pesanan serta kolom biaya pada pesanan adalah snapshot historis yang sengaja disimpan agar nilai transaksi lama tidak berubah ketika menu atau aturan biaya diubah.

4.4 Implementasi Kunci

Pencarian realtime dan filter. Kata kunci disimpan di variabel .obs; debounce GetX menunda request selama 400 ms, sedangkan perubahan kategori langsung memuat ulang data. Keduanya dikirim bersamaan ke server sehingga dapat dikombinasikan.

debounce<String>(keyword, (_) => fetchMenus(), time: const Duration(milliseconds: 400));
ever<int?>(selectedKategoriId, (_) => fetchMenus());

Keranjang reaktif. CartController didaftarkan permanen; total item, subtotal, dan badge dihitung dari items.obs sehingga setiap widget Obx ikut berubah otomatis. Penambahan jumlah dicek terhadap stok di aplikasi dan diperiksa ulang di server.

Checkout dalam satu transaksi. Server mengunci baris keranjang dan menu, memvalidasi ulang stok, membuat nomor INV, menyimpan pesanan beserta detail, mengurangi stok, lalu mengosongkan keranjang. Bila ada langkah yang gagal, seluruh perubahan dibatalkan.

$db->beginTransaction();
$items = $db->query('SELECT c.menu_id, c.jumlah, c.catatan_item, m.nama, m.harga, m.stok
                     FROM keranjang c JOIN menu m ON m.id = c.menu_id FOR UPDATE')->fetchAll();
// validasi stok ... jika kurang -> $db->rollBack() + HTTP 409
$prefix = 'INV-' . date('Ymd') . '-';                // NNN reset setiap hari
$stmt = $db->prepare('SELECT nomor_pesanan FROM pesanan WHERE nomor_pesanan LIKE ?
                      ORDER BY nomor_pesanan DESC LIMIT 1 FOR UPDATE');
$nomor = $prefix . str_pad((string) $urut, 3, '0', STR_PAD_LEFT);   // INV-20261014-002
// INSERT pesanan, INSERT detail_pesanan, UPDATE menu SET stok = stok - ?, DELETE FROM keranjang
$db->commit();

Aturan biaya. Biaya layanan Rp2.000, ongkir Rp8.000 hanya untuk tipe Diantar, diskon 10% bila subtotal ≥ Rp100.000; total = subtotal + biaya layanan + ongkir − diskon. Konstanta disimpan di api_config.dart dan config/database.php, dan nilai akhirnya dihitung ulang di server.

Error handling. ApiService membungkus setiap request dengan try-catch untuk timeout, server tidak terjangkau, respons kosong, dan respons bukan JSON. Pesan diterjemahkan menjadi kalimat yang mudah dipahami lalu ditampilkan dengan Get.snackbar atau tampilan error dengan tombol "Coba Lagi".

BAB 7 Contoh Struk PDF

Struk dibuat dengan package pdf dalam format kertas thermal 80 mm dan ditampilkan memakai PdfPreview dari package printing. Pengguna dapat menyimpan file ke folder Download aplikasi (path ditampilkan di snackbar) atau membagikannya. Berikut struk untuk pesanan INV-20261014-002 hasil pengujian checkout.

Teks struk memakai font bawaan PDF (Latin-1); karakter seperti tanda pisah panjang, kutip miring, dan emoji dari catatan pelanggan otomatis diganti atau dibuang agar PDF selalu terbaca.

BAB 8 Kesimpulan dan Saran

8.1 Kesimpulan

  • Aplikasi Delights berhasil dibangun dengan Flutter dan arsitektur GetX (controller, binding, route, Obx) yang terhubung ke MySQL XAMPP melalui REST API PHP dengan PDO.
  • Seluruh 12 fitur wajib terpenuhi: analisis & perancangan, setup GetX, CRUD kategori, CRUD menu + relasi, pencarian & filter, beranda/katalog/detail, keranjang, checkout, riwayat, dashboard, struk PDF, serta error handling dan pengujian.
  • Database dirancang ternormalisasi (3NF) dengan 5 tabel dan foreign key; checkout dan pembatalan berjalan dalam transaksi sehingga stok porsi selalu konsisten.
  • Atribut khusus tema kuliner (level pedas berwarna, suhu sajian, estimasi saji, best seller) dan catatan per item membantu pelanggan memesan sesuai selera.
  • Sebanyak 26 dari 28 skenario black box memberikan hasil sesuai harapan, 2 skenario khusus perangkat Android perlu dikonfirmasi di HP, dan 33 unit/widget test lulus.

8.2 Saran

  • Menambahkan autentikasi (login pelanggan dan admin) agar menu Kelola hanya dapat diakses kasir/pemilik kedai.
  • Menambahkan keranjang per pengguna dan notifikasi ketika status pesanan berubah.
  • Menambahkan pembayaran non-tunai (QRIS/e-wallet) dan pelacakan pengantaran.
  • Menambahkan fitur ulasan dan rating menu untuk membantu pelanggan memilih.

8.3 Cara Menjalankan Aplikasi

  • Jalankan Apache & MySQL di XAMPP, lalu import database/db_kuliner.sql melalui phpMyAdmin.
  • Salin folder backend/kuliner_api ke C:\xampp\htdocs\kuliner_api lalu buka http://localhost/kuliner_api/ untuk memastikan API aktif.
  • Jalankan flutter pub get lalu flutter run (emulator memakai http://10.0.2.2/kuliner_api; HP fisik memakai --dart-define=API_BASE_URL=http://<IP-laptop>/kuliner_api).
  • Build APK: flutter build apk --release → build/app/outputs/flutter-apk/app-release.apk.
